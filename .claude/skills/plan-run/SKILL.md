# Plan Run

Execute a YAML plan file generated by `/blueprint`. Tasks are dispatched to agents via the Task tool, with mandatory validation (checks) between tasks and git commits on success.

## Plan Format

Plans are YAML files in `.claude/plans/` with this structure:

```yaml
goal: '<description>'
issue: 42  # optional — GitHub issue number
checks:
    - name: <check-name>
      command: '<shell command, exit 0 = pass>'
steps:
    - name: '<step name>'
      tasks:
          - id: '<step.task>'
            summary: '<short description>'
            prompt: |
                <instructions>
            files: [optional/hints.ts]
            done: false # plan-run flips to true on completion
```

## Process

1. **Identify the plan file**: Use `$ARGUMENTS` to find the plan file path. If no path is given, look for `.yaml` files in `.claude/plans/` and list them for the user to pick.

2. **Parse and validate**: Read the YAML file. Verify it has `goal`, `checks` (with valid commands), and `steps` with at least one task. Report any structural issues and stop.
   - **Extract issue ref**: If the plan has an `issue` field (e.g. `issue: 42`), note it for use in commits and PR creation.

3. **Show the plan summary**: Display goal, step/task count, check commands, and which tasks are already `done: true`. If `$ARGUMENTS` contains `--task <id>`, note which tasks will be skipped. Ask for confirmation before proceeding.

4. **Execute tasks**: Process tasks in step order. For each task:

    a. **Skip if done**: If `task.done === true`, log it as already complete and move on.

    b. **Skip if before `--task`**: If resuming from a specific task ID, skip earlier tasks.

    c. **Dispatch to an agent**: Use the **Task tool** to run the task:
    - Use `subagent_type: general-purpose` for implementation tasks (file edits, code changes).
    - Use `subagent_type: Explore` for research-only tasks (finding files, understanding patterns).
    - Use `subagent_type: Plan` for planning/architecture tasks.
    - Build the agent prompt from the task's `prompt` field. Prepend: the plan goal, which files to read first (from `files`), and project conventions.
    - Set the agent description to the task summary.

    d. **Parallelize when safe**: Tasks within the same step that touch **different files** (check their `files` fields for overlap) CAN be launched in parallel using multiple Task tool calls in a single message. Tasks in **different steps** MUST be sequential. When in doubt, run sequentially — correctness over speed.

    e. **Run ALL checks after each task (or parallel batch)**: This is NON-NEGOTIABLE.
    - Run every check command from the plan's `checks` array using Bash.
    - Run them **sequentially** — stop at the first failure.
    - If a check fails: attempt to fix the issue yourself (read the error, fix the code, re-run). You get up to **3 fix attempts** per check failure. If still failing after retries, stop execution and report the failure.

    f. **Commit on success**: After all checks pass (unless `--no-commit` was specified), invoke the `/commit` skill with the task summary as the message hint. If the plan has an `issue` field, pass it as `--issue <number>` so the commit includes `Closes #N`. The commit skill handles staging, message drafting, pre-commit checks, and split detection. Do NOT manually `git add` or `git commit` — always delegate to `/commit`.

    g. **Mark done**: After a successful commit, update the plan YAML file to set `done: true` on the completed task. Use careful YAML editing — read the file, find the task by ID, add `done: true`, write back. Preserve formatting.

5. **Report results**: After all tasks, show a summary table:
    - Task ID | Summary | Status (done/failed/skipped)
    - Which checks failed (if any)
    - Total commits created
    - If any task failed, suggest resuming with `--task <id>`
    - If all tasks succeeded and on a feature branch (not `master`), suggest `/create-mr` to create a pull request

## Rules

- **ALWAYS run checks** after every task or parallel batch. No exceptions. No shortcuts.
- **ALWAYS run checks** even if the agent says "everything looks good". Trust the checks, not the agent.
- If checks fail, fix and re-run. If you can't fix after 3 attempts, STOP and report.
- **NEVER skip checks** to save time. The whole point of plan-run is validated, incremental progress.
- **ALWAYS use `/commit`** for committing — never manually `git add` / `git commit`.
- Do not push unless explicitly asked.
- Do not modify task prompts — execute them as written. If a prompt is unclear, do your best interpretation.
- Update `done: true` in the plan file after each successful task so re-runs skip completed work.
- When parallelizing, if ANY task in a parallel batch fails checks, do NOT commit the batch. Fix the failing task first, re-run checks on everything, then commit.
